# Target Library Attendance — New Android Project

## Included
- Responsive admin and student panels
- Supabase email/password authentication
- Dynamic, expiring attendance QR generated by an admin
- Student camera QR scanner
- Morning / Evening shifts
- Duplicate attendance prevention (database unique constraint)
- Attendance history and CSV student export
- Capacitor Android wrapper and PWA manifest

## Important: this is the source project, not a compiled APK
An APK must be built and signed in an Android build environment. The project includes the Android wrapper configuration. You will need Android Studio (or a compatible cloud build service) to produce the installable APK.

## 1. Create a free Supabase project
1. Open https://supabase.com and create a project.
2. Open Project Settings → API.
3. Copy the Project URL and the anon/publishable key.
4. In this folder, copy `.env.example` to `.env` and fill:
   - `VITE_SUPABASE_URL`
   - `VITE_SUPABASE_ANON_KEY`
5. Never put the `service_role` key in this app or in GitHub.

## 2. Create database
In Supabase → SQL Editor, run all of `supabase/schema.sql`.

## 3. Create the first admin account
1. Supabase → Authentication → Users → Add user. Create an email/password for the library admin.
2. Copy that user's UUID.
3. Run this SQL, replacing the UUID and email:
   `insert into public.profiles(id,email,full_name,role,is_active) values ('USER-UUID','admin@example.com','Library Admin','admin',true);`
4. Sign in from the app using that email/password.

## 4. Add student accounts
For this starter release, create student users in Supabase Authentication → Users → Add user, then insert their profile:
`insert into public.profiles(id,email,full_name,student_code,role,shift,is_active) values ('AUTH-USER-UUID','student@example.com','Student Name','TL001','student','Morning',true);`
Use unique student codes. For student passwords, set temporary passwords and share them privately; ask students to change them after first login. Do not publish credentials in a public repository.

## 5. Run locally
Install Node.js LTS, then:
```bash
npm install
npm run dev
```
Open the local URL shown by Vite. Camera scanning requires HTTPS or localhost.

## 6. Build Android project / APK
Install Android Studio and Android SDK, then:
```bash
npm run build
npx cap add android
npx cap sync android
npx cap open android
```
In Android Studio, build → Build Bundle(s) / APK(s) → Build APK(s).
For a release APK, use Build → Generate Signed Bundle / APK and keep the signing key safe.
If `android/` already exists, skip `npx cap add android` and run `npx cap sync android`.

## Security notes
- Supabase Row Level Security is enabled by the schema.
- QR tokens are random, short-lived, and stored server-side.
- Attendance is inserted only through a database function that checks session expiry, shift, profile status, and duplicate attendance.
- Do not disable RLS.
- The browser QR libraries load from public CDNs; the first load needs internet access.


## Admin workflow after setup
- Admin signs in and creates a new QR for Morning or Evening shift.
- QR expires after the selected 5–30 minute window.
- Students sign in, scan the QR using their phone camera, and the server checks eligibility and duplicate attendance.
- Admin dashboard lists attendance for today and exports student profiles to CSV.
- To add a student: first create an Auth user in Supabase Authentication → Users → Add user. Copy its UUID, then use the Add student account panel in the app to create the student's profile. The app intentionally does not collect or expose the Supabase service-role key.
